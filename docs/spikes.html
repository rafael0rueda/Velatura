Spike results

Phase 0 experiments, run on 2026-10-11 on Fedora 44 with GNOME Shell 50.5, GTK 4.22.5, libadwaita 1.9.4, GTK 3.24.52, Kitty 0.47.1 and Ghostty 1.3.1. Every experiment ran in throw-away directories with a private settings database; the real home directory and session were only read. The scripts are in spikes/ and can be re-run.

1. Status of the open questions

Nine of the fifteen questions from the review are answered or partly answered. Six are moved to the phase that needs them, each for a stated reason. Results hold for the versions above; other versions are not yet tested.

2. GTK4 and libadwaita

Script: spikes/gtk4_css.py. Each case starts a fresh process with its own configuration directory and asks GTK what window_bg_color resolves to. The theme wants #aa0000; the user's own file says #111111.

CaseResultMeaning
@import on the first line, user's definition below#111111The user's line wins. This is the "set up but not taking effect" case predicted by the review.
User's definition first, @import on the last line#aa0000The theme wins, with no parser warning.
A style rule, then the user's definition, then @import#aa0000GTK does not require imports to come first.

gtk.css is a symlink into another folder; the imported file sits beside the link#aa0000The import resolves relative to the link's folder, not the real file's.

Consequence for the plan: the connection line goes at the end of gtk.css. On this machine that makes the GTK target effective without touching the roughly 60 existing definitions.

4. GNOME Shell

Script: spikes/shell/run.sh. It starts a headless GNOME Shell with its own D-Bus session, settings database and data folders, loads the real User Themes extension and a small probe, and records the panel's computed background after each step.

StepPanel backgroundMeaning
Stock theme, dark style#000000Baseline.
Theme A: one rule, #aa0000#aa0000, panel height unchangedA user theme is a layer over the stock stylesheet. Overrides alone are enough.
Theme A's file rewritten to #00aa00#aa0000No reload when the file changes.
The same name set again#aa0000No reload when the name is unchanged.
Theme B under a new name, #0000aa#0000aaA new name reloads at once.
High Contrast turned on#0000aaThe override stays active, so the app must skip Shell recolouring itself when High Contrast is on.
Light style#0000aaThe override stays active across the light and dark switch.
A stylesheet with syntax errors followed by a valid rule#000000One syntax error rejects the whole file. The Shell logs the error, falls back to the stock look and keeps running.
Theme name cleared#000000Clean return to stock.

Consequences for the plan: a generated Shell stylesheet must be checked for syntax before it is installed, because a single error silently removes the whole theme. The failure mode is safe: the Shell stays usable.

6. Matching the system accent

The review recommended choosing the nearest of GNOME's nine accents by colour distance. Tried and rejected: by distance, Aetherius's periwinkle and most pastel accents land on slate, and Ember's orange lands on yellow. The rule now implemented: a near-grey colour maps to slate; any other colour maps to the accent with the nearest hue. With it, Aetherius maps to blue and Ember to orange, and a set of pastel test colours each map to their own hue. The nine values were read from the installed libadwaita.
