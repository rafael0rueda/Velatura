Phase 2b – icons, cursor, wallpaper, fonts and Flatpak apps

Branch phase-2b-selections. Completed 2026-10-12. The second slice of Phase 2 (D47). Its exit condition in the roadmap: transaction tests pass for each. They do.

On the owner's desktop nothing was changed. The installed icon themes, wallpapers and current settings were read to see what the lists have to cope with; no choice was made and Flatpak's overrides file was only read. It already grants both folders, so on this machine the Flatpak part has nothing to add.

Added

  • Icons, cursor, wallpaper and three fonts, chosen among what is installed: in a new group on the Apps & Desktop page, and with velatura look, look list, look set and look reset. A choice takes effect at once, is a backup in History like any other change, and Undo reverses it. It belongs to the user and the machine, not to a theme, so it stays when the theme changes, by hand or on schedule.
  • What can be chosen. Icon and cursor themes are the folders found in the user's and the system's icon folders, by exact name. Wallpapers are the pictures in the backgrounds folders, or a picture of the user's own given by its full path; the one picture is set for both the light and the dark style. A font is a name and a size: the app uses the desktop's own font chooser.
  • Suggestions from a theme. A theme file may name an icon and a cursor theme. The theme's page shows them, says whether they are installed, and offers Use. Nothing is applied without that press (D7).
  • Flatpak apps. A new part, Flatpak Apps, adds read-only access to the two GTK settings folders to Flatpak's per-user overrides, for every app, so the colour files reach sandboxed apps. It is off until turned on, because it widens every sandbox a little, and the first edit of an existing overrides file needs agreement like every other file of the user's.
  • Editing a list inside a key file. The overrides file has no place for a marker, so Velatura records exactly which list members it added and whether it had to make the key or the group. Undo takes out those and nothing else, from the file as it is then. Members that were already there, in any mode or as a denial, are the user's: they are not claimed and never removed.

Tests and checks

  • Seven transaction tests for the two parts: apply and undo give back six kinds of overrides file byte for byte, also through Remove Everything; edits made around the added members survive undo; members removed by hand are reported and not put back; and the exhaustive crash test covers the Flatpak edit and a choice.
  • Five tests of the key-file editor over thirteen file shapes: no file, empty group, missing final newline, Windows line endings, lists with and without a closing separator.
  • Only installed names can be chosen: a name with a path in it, a fallback theme, a cursor-only theme given as icons and a file that is not a picture are all refused. A name from a theme's index file is shown with control characters removed.
  • The command end to end in a private session with a real settings store.
  • 110 tests in all. The translation template has 216 strings.

Changed from the plan

  • A choice is its own change, made at once (D50), not something applied with the next theme. The plan said only that the choice is the user's and is stored with the user's settings; the desktop's own settings are that store.
  • The Flatpak edit reuses the record of a marked line instead of the separate "structured edit" change of the architecture: the same fields describe it, and one more holds what was added.

Not done in this slice

  • Flatpak access per app. Only the override for all apps is offered.
  • A different choice by day and by night. The choices are one set.
  • A file chooser for the wallpaper in the app. The app lists the installed pictures; a picture of the user's own is set from the command.
  • GNOME's paired light and dark wallpapers are listed as two pictures, not as one pair.
  • Turning Flatpak Apps on does nothing until the next apply, like the other switches on that page.
  • Not checked in a real Flatpak app: that the colours arrive once access is granted. It is how the owner's machine is set up today, by hand.
