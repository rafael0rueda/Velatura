Phase 0 – spikes and repository skeleton

Branch phase-0-spikes. Completed 2026-10-11.

Added

  • Planning documents, revision 2: plan, architecture, theming targets, decisions log and review findings, with the owner's answers of 2026-10-11 recorded.
  • Workflow page and this changelog.
  • Spike results page, with the scripts that produced it in spikes/: GTK4 stylesheet precedence, GTK3 with and without adw-gtk3, and User Themes behaviour in a headless GNOME Shell.
  • Cargo workspace with three crates and no third-party dependencies:
    • velatura-theme: the typed colour (strict parsing, a closed set of formatters), WCAG contrast, OKLab conversion, and matching a colour to the nearest GNOME accent.
    • velatura-engine: the first piece of the host-access layer: XDG directory resolution and an atomic file write that writes through symlinks and keeps permissions.
    • velatura-cli: a skeleton velatura command (--version, accent, dirs).
  • Test gate scripts/check.sh: formatting, lints as errors, tests, and a documentation check (balanced tags, working links and anchors, nothing loaded from the network).
  • GitHub Actions workflow running the same gate in a Fedora 44 container, and scripts/check-in-container.sh to run it the same way locally.
  • Licence file (GPL-3.0-or-later).

Changed in the plan because of the spikes

  • GTK connection line goes at the end of gtk.css, not the top. It then wins over definitions already in the file.
  • Generated Shell stylesheets are syntax-checked before installing. One error makes the Shell reject the whole file.
  • System accent is matched by hue, with a grey threshold, not by colour distance.
  • Kitty reloads by itself on the tested version; the instruction to the user depends on the Kitty version.

Tests

15 unit tests pass: 10 in the theme crate and 5 in the engine crate. Lints pass with warnings treated as errors. The documentation check passes. The whole gate, including formatting, was run in a Fedora 44 container with scripts/check-in-container.sh, because rustfmt is not installed on the host.

Not done in this phase

  • Six of the fifteen open questions are moved to later phases, each with its reason, in Spike results. The main ones: older libadwaita versions (Phase 2), exact undo and role sufficiency (Phase 1a), GUI build measurements (Phase 1c, blocked on development packages that need sudo).
  • Results are for GNOME 50.5 only. GNOME 51 is not installed as a session on this machine.
  • The GUI crate and the Meson build are not created yet.
  • Nothing was applied to the live desktop. The old theme-auto.timer is untouched and still active.
