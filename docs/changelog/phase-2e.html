Phase 2e – Spanish, GNOME 47 to 49, and Ubuntu's session

Branch phase-2e-reach. Completed 2026-10-13. The last slice of Phase 2 (D47). Its exit condition is that of Phase 2 itself: a theme can be created in the GUI and switches on schedule without the GUI running. That was met with slices 2a and 2c; this slice widens where it holds.

On the owner's desktop nothing was changed. The older GNOME versions and Ubuntu were reached through containers.

Added

  • The app in Spanish. All 354 sentences of the app and of the messages it shares with the command are translated. The app speaks Spanish when the session asks for it (LANG, LC_MESSAGES, LANGUAGE, read the way gettext reads them) and English otherwise.
  • Translations travel inside the program. The catalogs in po/ are compiled in and read by a small reader of Velatura's own, so they are found the same way from a build folder, an install and a package, with nothing to install beside the program. This closes the open point from Phase 1e that catalogs were only loaded once the app was installed with its data.
  • A translation cannot fall behind unnoticed. A test fails if any sentence has no Spanish, if a translation loses something to fill in ({1}, {name}), an access key, a full stop or an ellipsis, or if a reason for leaving something out does not begin the way the app expects. scripts/update-pot.sh brings each catalog in step with the sources.
  • GNOME 47, 48 and 49 in CI. The whole gate now also runs on Fedora 41, 42 and 43, against each release's own GTK, libadwaita and compositor: the tests, GTK accepting the generated stylesheets, a libadwaita app computing every colour, and the app driven through apply, undo, the schedule and the editor.
  • An unchecked GNOME Shell is left alone. Velatura asks the running Shell its version. On one outside 47 to 51 the top bar and overview are left out, with the reason, unless the part is named outright with --only gnome:shell.
  • Ubuntu's session. Ubuntu's own session uses its own Shell stylesheet, Yaru, in a light and a dark form. The selectors of both were taken from Ubuntu 24.10, 25.04, 25.10 and 26.04 (GNOME 47 to 50), and a test checks that everything Velatura overrides is there. scripts/shell-selectors-ubuntu.sh takes them again for a new release.

Tests and checks

  • Five tests for the catalogs: complete and well-formed Spanish, the language taken from the session, and the reader on escapes, plurals, long lines and fuzzy entries.
  • One test for the unchecked Shell version, and one for Ubuntu's selectors.
  • The app rendered in Spanish with scripts/gui-shots.sh --lang es; one tab label was shortened because it did not fit.
  • 137 tests in all. The template has 354 strings.

Changed from the plan

  • No gettext at run time (D53). The plan had gettext load catalogs installed by Meson. Reading the same .po files from inside the program needs no install step and no further library, and gettext's tools still make and check the catalogs.

Not done, and what only a person can do

  • The command stays in English. Its help and its own short lines are not translated in this slice; mixing them with translated sentences would read worse than English throughout.
  • The Spanish has not been read by a second person. It was written with the app's wording rules in mind (neutral, no "tú"), and checked by rendering, not by a native reviewer other than the owner.
  • Languages that count differently (more than two plural forms) need a rule the reader does not have yet.
  • A real Shell on 47 to 49 and on Ubuntu: checked there by the lists of selectors only. A Shell cannot be started in a container; the live Shell check runs on GNOME 50.
  • Ubuntu's own extensions (the dock among them) bring their own colours, as other extensions do; Velatura's extension is the answer there too, and was not tried on Ubuntu.
  • Still open from the MVP's list: screen reader and keyboard-only use, and the lock screen, need a person at the real session.
