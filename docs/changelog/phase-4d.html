Phase 4d – recolored pictures and cursors

Branch phase-4d-pictures. Completed 2026-10-14. The fourth of five slices of Phase 4 (D59). Its exit condition, that transaction tests pass for each, holds for icon themes made of pictures and for cursors.

On the owner's desktop nothing was changed. Frost-Aetherius and capitaine-cursors were read and recoloured into throw-away home folders that point at them.

What it does

  • Icon themes made of pictures are recoloured by Recolored Icons as drawn ones are (D58): the family is the hue the folder pictures share, its main colour the one they are filled with, and each pixel of that hue moves to the accent with its lightness relative to the main one kept. Pixels at the family's edge move part of the way, so edges stay smooth; transparency, greys and other colours stay; app icons are not touched. Where the accent is the icon theme's own colour, the set is still made.
  • Recolored Cursor, a part of its own on Apps & Desktop under Desktop, off until turned on: a cursor set beside the icon sets, from the cursor theme in use, with the cursor set to it. Greys go along the line from the theme's darker colour to its lighter, so the body and outline keep their contrast; coloured parts take the accent's hue. Only pixels change: every other byte of a cursor file stays.
  • Sets of each kind are cleared by their own part only: recolouring icons never takes a cursor set away, nor the other way round. An icon theme whose name starts like a cursor set's is told apart.
  • The preview, the result and History say each set in one line: "Create the cursor set … with 99 recolored cursors".

Tests and checks

  • Three tests of the PNG code: what is written reads back the same; PNG's own checksum; damaged, cut, sixteen-bit and interlaced pictures give nothing. One test of pixel recolouring, three of cursors (body, outline, half-transparent pixels and the spinner; damaged files refused; a light theme).
  • A transaction test for a small icon theme made of pictures, written by libpng: the marked pictures and a link to one in the set, a grey one and an app icon left out, the folder's body in the accent, alpha kept, another theme, two undos to the exact start.
  • Four transaction tests in tests/cursor_sets.rs for a small cursor theme: off until turned on, the set with its alias copied and a file that is not a cursor left out, the arrow's outline and body in the theme's colours, another theme clearing the first set, undo bringing it back; a crash at every step, from a clean home and an applied one; a switch with no one present keeping earlier sets, and icons leaving cursor sets alone; cursor themes that cannot be recoloured.
  • In the gate, scripts/icons-accept.sh now also recolours the two fixtures with the command: GdkPixbuf must load every picture in the set and find the folder in the accent, a reader that is not Velatura's must read every cursor and find the arrow in the theme's colours, and undo must put both back.
  • 232 tests in all. The translation template has 413 strings, all in Spanish.

Changed from the plan

  • The cap on crates is 47, not 45 (D63, accepted by the owner).
  • Cursors are a part of their own, off until turned on, as recoloured icons are; the plan did not say.

Not done, and what only a person can do

  • Not looked at by a person in a real session: the pictures and cursors were looked at side by side with the originals, on light and dark grounds. How Frost-Aetherius in Ember reads in Files, and the cursor over real windows, is part of the owner's full test. GTK 4 apps load a new icon theme at once; other toolkits, and some apps for a new cursor, may need restarting.
  • Pictures other than PNG (XPM, sixteen bits a channel, interlaced PNG) are left as they are.
  • An already retinted theme such as Frost-Aetherius is recoloured from its present colours: its faint tint of periwinkle in the greys moves part of the way too.
