Phase 1a – engine and command line

Branch phase-1a-engine-cli. Completed 2026-10-12. Exit condition from the roadmap: the exhaustive crash test passes. It does.

Nothing was applied to the owner's desktop. Every test ran in a throw-away home folder, and the one test that uses the real settings store runs it inside a private session with its own database. On the real machine only the read-only commands were run (doctor, status, apply --preview). The old theme-auto.timer is untouched and still active.

Added

  • Interface guidelines page (hig.html): the GNOME Human Interface Guidelines applied to Velatura, eight corrections to the planned GUI, and the acceptance checklist for the GUI phase. Decisions D36 and D37.
  • Theme file format: parser and validator for the TOML format of the plan. Size cap before parsing, version check before anything else is read, every colour typed, one-level references into the palette, unknown keys and slots reported as warnings, every problem reported with its location. Derivation rule 1 fills the optional interface roles and is frozen by a test.
  • Aetherius and Ember as bundled themes, converted from the existing palettes. All 45 named colours of each are carried without loss, and every role is written out, so nothing is left to derivation.
  • Kitty: a colour file Velatura creates (velatura.conf, 30 settings) and a marked block at the end of kitty.conf holding the one include line. Reports lines after the block that would override the theme, and Kitty's automatic theme files.
  • Dark style and accent colour through the desktop settings, with the accent set to the nearest of GNOME's nine. A value the user had set is told apart from a default, and is restored as it was.
  • Backups, undo and restore. Before anything is changed its content is stored. Each change is recorded in a numbered backup. undo reverses the latest; restore <id> goes back to the state before that backup; restore --original removes everything Velatura added, using a ledger of first-seen states that is never pruned. Twenty backups are kept.
  • Undo keeps the user's later edits. A block is taken out of the file as it is now; a file or setting changed outside Velatura since is left alone and reported.
  • Journal and crash recovery. A journal is written before the first change and removed after the last. An interrupted run is rolled back at the next start, and only items that still hold exactly what that run wrote are restored.
  • Preview is the plan that runs. --preview prints the plan; applying executes that same plan and stops if anything it was computed against has changed.
  • Agreement before the first edit of a user's file. On a terminal the command asks; without a terminal and without --yes it changes nothing and exits with code 3.
  • Command line: list, show, validate, targets, status, apply, undo, history, restore, recover, doctor; --preview, --yes, --only, --except, --replace-changed, --json. The help text carries the recovery commands for a text console. All text is US English and follows the writing rules of the interface guidelines.
  • One lock for every change, held through the operating system, so it cannot outlive a process that died.

Open questions answered

  • Exact undo (question 9): yes, byte for byte, shown by the tests above.
  • Are the roles sufficient? (question 10): yes for both themes and for Kitty. Two things have no role and were left out: Kitty's two extra indexed colours (16 and 17), and separate tab-bar colours, which are now taken from the interface roles.
  • Kitty's automatic reload (question 8): Kitty 0.47.1 hands only the top-level settings file to its watcher, according to its source. Whether a change to an included file alone triggers a reload was not tested, because that needs a Kitty window on the desktop. The command therefore tells the user how to reload by hand if windows keep the old colours.

Changed from the plan

  • "One line" is a block of three: two marker lines around the include line, so the app can find and remove exactly what it added.
  • Dependencies. Four were added: toml (reading theme files), serde_json (backups and state), sha2 (content hashes) and gio (desktop settings). The command now links 41 third-party crates, most of them brought in by gio; the gate fails above 45. Decision D38.
  • Size and start-up: the release binary is 1.1 MB (333 kB for the Phase 0 skeleton) and starts in under 1 ms.
  • Minimum Rust is 1.89, for the standard library's file locking.
  • Continuous integration installs the GLib development files and a private settings store, and runs the end-to-end test.

Not done in this phase

Stated plainly, with where each goes.

  • Nothing has been applied to the real desktop. The first real apply waits for the owner's go-ahead, together with the decision about the old timer.
  • Kitty on this machine will not show the theme yet: dark-theme.auto.conf exists and Kitty puts it above every other colour setting. The command detects and reports it; it does not rename the file. What to do about it is the owner's call.
  • Extended attributes, access lists and security labels are not copied when a file is replaced. A new file gets the folder's default label, which is correct for files in the home folder, but the general case is open. Phase 1b.
  • Hard-linked files are not detected; replacing one breaks the link. Phase 1b.
  • Detection of dotfile managers, of a running app, and of an editor holding the file open. Phase 1b, with the other detection work.
  • Change kinds not needed yet: links, key-level edits of structured files and generated folders arrive with the targets that need them.
  • Commands not built yet: switch, schedule, disconnect for a single target, theme import and export. restore --original covers "remove everything".
  • A fixture of a first-version backup that every later build must restore. It can only be frozen once the format has shipped; added at the end of Phase 1b.
  • Failure cases not yet tested: a really full disk, immutable files, a home folder that is itself a link, two processes racing for the lock from start to end.
  • Fuzzing of the theme parser and the licence and advisory checks on dependencies. Phase 1b.
  • A lint that forbids file access outside the host layer. The rule is followed by hand for now.
  • Translation. All text is in one module, ready for it; the machinery comes with the GUI in Phase 1c.
