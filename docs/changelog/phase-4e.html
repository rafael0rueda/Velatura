Phase 4e – releases

Branch phase-4e-releases. Completed 2026-10-15. The last of five slices of Phase 4 (D59). Its exit condition is Phase 4's: Velatura can be installed without building it from source. The release workflow builds a tarball of the programs that installs for one user and runs; it was run in full in a Fedora 41 container here, and it runs on the pull request in GitHub Actions. With it Phase 4 is complete. The first release, 0.1.0, is published by pushing its tag after this is merged.

On the owner's desktop nothing was changed. Every install was into a throw-away home folder.

What it does

  • Version 0.1.0 (D65), shown by velatura --version and the app's About.
  • install.sh puts the command and the app in ~/.local/bin and the launcher and icons under ~/.local/share, without root; --prefix another full path; --uninstall takes exactly those files out again. The launcher names the app by its full path, so it starts whether or not the folder is on the session's path. Uninstalling leaves the desktop as Velatura left it; velatura restore --original first takes Velatura's changes away.
  • scripts/release.sh builds all of it into dist/, with fixed times, owners and order inside each tarball.
  • The release workflow, .github/workflows/release.yml: on a tag v<version> it checks the tag is the version in Cargo.toml, builds on Fedora 41, checks the checksums, installs the programs into a throw-away home, runs them, uninstalls them and finds nothing left, builds the source with no network and an empty cache, and only then publishes the release with notes on how to install. On a pull request that changes any of this it does everything but publish.
  • Qt apps (D66): no built-in part; a template for qt6ct comes in each release and in Theming targets, with the two steps that switch qt6ct on. Its format was taken from a colour scheme inside the qt6ct package.
  • How to release is a section of the workflow; the README says where releases are.

Tests and checks

  • The workflow's steps, run in a Fedora 41 container as GitHub runs them: built, installed, run, uninstalled, built offline from the source tarball, with a tag of v0.1.0.
  • The programs built on Fedora 41 run on the owner's Fedora 44: no library missing, the command answers, the app starts in a headless session.
  • One test that the qt6ct template is accepted and writes three lines of Qt's 21 roles as #AARRGGBB.
  • 233 tests in all. The translation template has 413 strings, all in Spanish.

Changed from the plan

  • GitHub Releases only, as the owner chose (D59): COPR, AUR and a Flatpak repository are not made.
  • Qt is settled as a template, not a part (D66).

Not done, and what only a person can do

  • x86_64 only. No build for ARM.
  • Not signed. The checksums show a download is whole; they do not prove who made it.
  • The extension is not uploaded to extensions.gnome.org: that needs the owner's account and GNOME's review.
  • qt6ct was not run with the template's output.
  • The owner's full test of the app on the real desktop, which the owner set on 2026-10-14 for when the app is complete, comes next, and can use this release.
