Phase 3d – recolored icons

Branch phase-3d-icons. Completed 2026-10-14. The last of the four slices of Phase 3 (D54). Its exit condition is that of Phase 3: each target passes the same transaction tests. Recolored icons do, and so Phase 3 is complete.

On the owner's desktop nothing was changed. The two vector icon themes installed there, Tela purple and Fluent purple, were read and recolored into throw-away home folders, which point at them, to measure and look. The icon theme in use there, Frost-Aetherius, is made of pictures and is not something this slice recolors (D14).

What it does

  • A part of its own, off until turned on: Recolored Icons, on Apps & Desktop under Desktop, and icons:recolor in the command. Turning it on is the agreement; it then follows every apply and every switch.
  • Only the icons that carry the icon theme's own colour. An icon theme that draws its folders in a colour of its own (the purple of Tela purple, the blue of Adwaita) uses that colour and a few shades of it wherever it marks something. Those shades are found in its folder icons, and each is moved to the theme's accent, keeping how much lighter or darker than the main one it was, so the shading of every icon stays. Every other colour in an icon, and every byte that is not a colour, stays as it was.
  • Not touched: app icons, whose colours are their makers'; symbolic icons, which already follow the text colour; and every icon without the marked colour.
  • A small icon theme of Velatura's own. The recolored icons go into ~/.local/share/icons/Velatura-<theme>-<hash>/, whose index.theme names the icon theme it was made from as the one to look in for everything else, and is hidden from lists of icon themes to choose. The desktop's icon theme is set to it, last. Its name changes with what it holds, because GTK loads an icon theme again only when the name it is given changes.
  • The icon theme in use is the one recolored. When it is already a set of Velatura's, the one it was made from is. Choosing another icon theme (Icons, on the Themes page) and applying recolors that one; choosing the original again gives the icons back as they were.
  • Sets for earlier colours are taken away by an apply with someone present, like the Shell's theme folders (D29), and come back with Undo. A scheduled switch never takes one away: switching between a daytime and a nighttime theme leaves two sets, and each is used again as it is.
  • Left out, with the reason: an icon theme with no colour of its own (all grey, or made of pictures, which is Phase 4), one that is not installed, one that would need more than 20,000 icons or 48 MB, and everything while High Contrast is on.
  • Said in one line. The preview, the result and History say "Create the icon set … with 852 recolored icons", not one line per icon; the app's confirmation says how many icons it recolors.

Tests and checks

  • Four tests of the colour logic: the main colour and its shades are found in folder icons and greys are not; the main colour becomes the accent and lighter and darker shades stay lighter and darker; only those colours are replaced, upper and lower case and short forms alike; an index.theme is read only for what is plain, and written back.
  • Seven transaction tests with two small fixture icon themes, one drawn and one of pictures, in tests/icon_sets.rs: off until turned on; the marked icons and nothing else; the same colours again change nothing; another theme makes another set and clears the first; two undos back to the exact start; a crash at every step, from a clean home and from an applied one; a switch with no one present never takes a set away; an icon edited in a set is kept with its folder; themes that cannot be recolored; a folder of that name that is not Velatura's; a set is not offered as an icon theme, and the next one is made from its original.
  • In the gate, against GTK: scripts/icons-accept.sh has the command recolor the system's Adwaita in a throw-away session. GTK is asked where it finds icons, the way an app asks: the folder must come from the set, other icons from Adwaita. Every icon in the set must load, and the folder must be drawn in the accent's hue. Undo must put Adwaita back and take the set away. A set whose folder was not recolored fails it.
  • 181 tests in all. The translation template has 384 strings, all in Spanish.

Changed from the plan

  • A set is ordinary files, not a tree with a recipe (D58, accepted by the owner on 2026-10-14). The architecture had generated sets staged in ~/.cache, moved into place in one rename, and recorded in backups as a recipe to rebuild from. A set turned out to be a few hundred icons and a few megabytes, not thousands. Written as files of Velatura's own, it uses the transactions, crash recovery and undo that every other target has been tested with, and backups keep its files once each.
  • Off until turned on, like Flatpak Apps: the plan did not say. The icon theme is the user's choice (D50).

Not done, and what only a person can do

  • The owner's icon theme is made of pictures and is left out: recoloring pictures is Phase 4, experimental.
  • Not looked at in apps by a person. GTK was asked where it finds icons, and the folder icons were drawn and looked at for Tela purple and Adwaita. How the icons read in Files, the Shell and other apps needs a person at a real session. GTK 4 apps load the new icon theme when the setting changes; other toolkits may need restarting.
  • Turning the part off leaves the icons as they are, like turning off any other part. To have the original icons back: choose the icon theme again under Icons, or Undo.
  • When an icon theme is updated by its package, a set made from it is made again only if its folder icons or index.theme changed; other icons wait for the next new colours.
  • Themes whose marked colour is not in their folder icons (some draw folders in a fixed colour and mark other things with another) are recolored in their folders' colour only.
