Release 0.2.0

Prepared on branch release/0.2.0, 2026-10-18. Everything merged since 0.1.0 (2026-10-15): pull requests #24 to #51, decisions D70 to D78. Most of it came from the owner's first weeks on their own desktop, and from the deep review of 2026-10-17.

Upgrading from 0.1.0. Install as before. Velatura's Shell extension is now at version 6: velatura extension install (or Install on Apps & Desktop), then sign out and in. A part turned off on Apps & Desktop is now taken away at the next apply by hand (D78); see below.

New

  • Window Outline (D71, #30, #32): a thin line in the theme's accent around the window in use, drawn by Velatura's extension; off until turned on.
  • Top Bar Style (D74, #35): the top bar as one complete bar or as a pill per button, as opaque as chosen; off until turned on. Also from the command: velatura top-bar.
  • UPS Indicator (D75, #36): the watts a UPS draws, in the top bar, read from Network UPS Tools on this computer, with battery and runtime in a menu; off until turned on.
  • A redesigned window (D72, #33): the theme in use as a card, every theme as a card in a grid with a Dark and Light filter, Day and Night as one group, icons and counts on Apps & Desktop, History grouped by day. A new app icon.
  • Each theme card has its own menu button (D77, #43), with Preview Changes… in it (#51): what applying the theme would change, with the details, before anything is changed (D37).
  • A part turned off is taken away at the next apply by hand (D78, #44): it goes back to how it was before Velatura instead of keeping the last theme's colours. Not by the schedule, nor with --only or --except; undo brings it back.
  • Other tools (D76, #38): Shell extensions that keep a colour in their own settings are listed among the other tools that change colours.
  • Recoloured sets (#25): the sets of recent themes are kept, so coming back to one is quick; the app shows work while it makes one, and says when they show.
  • README (D73, #34, #50): what Velatura does, with pictures of the app.

Fixed

  • Undo could reverse the wrong change: one a run with another home folder had left among the backups, an older one when the newest could not be read, or one after its preview no longer held. It now refuses and says which file is in the way; it also no longer puts back a block taken out by hand (#39).
  • A program listening on NUT's port could keep the UPS reading going for ever; a reading now ends after 3 seconds or 64 KiB (#40).
  • The app lost its place on every change; Ctrl+Z typed in a text field undid the desktop; unsaved work in the theme editor could be lost without asking (#42).
  • Recolored Icons read as not applied right after every theme switch (#45).
  • The top bar was reported as themed while another extension coloured it (#24); a light theme now asks for light outright, so the Shell's menus stay readable (D70, #27); the dash and app grid tiles no longer get a solid background (#28).
  • Starship's prompt, Neovim's colour scheme and Solaar's tray icon after a switch (#26, #29); a part turned on or off can be applied without changing theme (#31).

Words

  • "Undo Last Change" in place of "Undo Last Apply"; History's button says "Go Back to Before This Change…"; the app points to its own Install button instead of naming commands; Spanish no longer uses "aplicación" for an apply (#46).
  • Errors say which file and what is wrong with it, the same in the command and the app; the app's banner says when Velatura's own records cannot be used (#47).
  • The command refuses a part or variant name that does not exist, with the right ones (exit 2), says that apply needs a theme, and keeps the targets table in line (#48). Its help no longer says "you".

Build and release

  • A release is published only from a tag on main, after the whole gate passes in the release build itself, with the toolchain it is built with (#41).
  • Every CI job has a time limit and package installs try again (#37); the Shell extension is parsed on every image, the licence check reads SPDX expressions properly, and every part is planned by name in a test (#49).
  • Architecture describes what was built (#50).

Known and left

  • Velatura's records for the schedule and the extension treat a file from a newer version as missing. Every file is version 1, so this only matters after a future version and a downgrade.
  • Part names are written out in more than one crate; nothing a person sees depends on it.
