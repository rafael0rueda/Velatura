Phase 3b – themes from base16, base24 and Kitty files

Branch phase-3b-importers, on top of Phase 3a. Completed 2026-10-13. The second of four slices of Phase 3 (D54). Its exit condition: an imported theme applies like any other. It does, and the command's test applies one in every run.

On the owner's desktop nothing was changed, and no theme was added to the real library.

Added

  • Import reads three more kinds of file. A base16 scheme, in the older layout (scheme: and sixteen base00 to base0F lines) or the newer one with a palette: section; a base24 scheme, which adds eight colours; and a Kitty theme, as Kitty's own theme collection writes them. Import in the app (Ctrl+O) and velatura theme import <file> take them as they take a theme file. The file dialog also shows .yaml, .yml and .conf files.
  • The result is an ordinary theme. It is stored as a theme file with every colour written out, can be edited, exported and applied like any other, and keeps nothing of the file it came from but its colours and its name, author and licence. The question before importing, and the command, say which kind of file it was and that colours it does not give were worked out.
  • From a base16 scheme: background, text, surface, selection, the two quieter text colours, and blue (base0D) as the accent; the sixteen terminal colours as base16's own terminal templates number them; fourteen colours for code, following the format's styling guidelines; and the scheme's own colours kept under their own names in the theme's palette. A base24 scheme also brings its six bright terminal colours and its darker background.
  • From a Kitty theme: background, text, the sixteen terminal colours, selection, cursor and link colour. Kitty has no accent, so the border of the active window is used where the theme sets one, and blue otherwise. Values that are not colours (none, background) are passed over.
  • A file that lacks colours says which. "A Kitty theme without all the colors a theme needs. Missing: color1, color2". Nothing is stored.

Tests and checks

  • Six tests of the reader, with real schemes as fixtures (Ocean in both base16 layouts, One Light as base24, Dracula for Kitty): the two layouts give the same theme; a Kitty theme written back out for Kitty has every colour it came with; what Velatura writes for Kitty reads back with the same terminal colours; what is missing is named; a script, a settings file and an empty file are not themes; hostile text in a scheme's name stays a cleaned, capped name and cannot add a variant.
  • One test of the library: the three kinds stored, listed and refused on a clash like any theme; a file of Velatura's own with a mistake is still reported as that.
  • 20,000 damaged copies of the fixtures go through the reader: nothing panics, and whatever is read passes the validator and reads back as itself.
  • The command end to end: a Kitty theme and a base16 scheme imported, shown and applied.
  • 160 tests in all. The translation template has 371 strings, all in Spanish.

Changed from the plan

  • No YAML library (D56). A base16 scheme is a flat list of key: value lines. A reader of a few lines takes what is needed from it; a YAML parser would be a further third-party crate in the command, which stands at 44 of the 45 allowed.
  • One import for all formats. The plan spoke of importers; there is no separate command or menu item. The file's content, not its name, says what it is.

Not done, and what only a person can do

  • The file dialog was not opened by a person: a headless session cannot show it. The path behind it is the one the command's test takes.
  • Only the single-file forms. A base16 scheme is not fetched by name from the collections online, and Kitty's include lines are not followed: only the file given is read.
  • Colours written as names or in short form (red, #fff) in a Kitty theme are passed over, as if not given. Kitty's own collection writes six digits.
  • base16's choice of red for variables is kept as its guidelines have it. It can be changed in the editor under Code.
  • Whether an imported theme reads well everywhere depends on the scheme: some give quiet text colours below the contrast the editor asks for. The editor lists those and offers Fix; import does not change a scheme's colours by itself.
